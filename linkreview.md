# Обзор литературы

## Фокус обзора

Тема проекта — перенос группового знания в нейронных процессах для рекомендаций новым пользователям. Основной вопрос: может ли использование знания, полученного от других пользовательских задач, ухудшать рекомендации по сравнению с моделью, использующей только личную историю, и какие свойства механизма переноса связаны с таким ухудшением.

В обзор включены 25 работ. Они разделены на четыре группы:

1. базовые и последующие методы cold-start-рекомендаций на основе метаобучения;
2. альтернативные методы переноса знания при холодном старте;
3. нейронные процессы и механизмы адаптации, на которых построены TaNP и FANP;
4. работы о конфликте задач и негативном переносе, необходимые для формализации исследовательской гипотезы.

## 1. Основные методы cold-start-рекомендаций

### 1. TaNP — Task-Adaptive Neural Process for User Cold-Start Recommendation

**Источник:** X. Lin et al., WWW 2021, pp. 1306–1316. [Статья](https://arxiv.org/abs/2103.06137) · [Код](https://github.com/IIEdm/TaNP)

- **Идея.** Каждый пользователь рассматривается как отдельная задача. Модель обучает центроиды пользовательских задач, мягко сопоставляет нового пользователя с ними и объединяет личное представление с групповым знанием.
- **Значение для проекта.** Это исходный воспроизводимый бейзлайн и непосредственный объект анализа механизма переноса.
- **Ограничение.** Среднее качество не показывает, существуют ли отдельные пользователи, для которых групповое знание вредит; механизм смешивает личное и групповое представления до предсказания.

### 2. FANP — Towards Flexible and Adaptive Neural Process for Cold-Start Recommendation

**Источник:** X. Lin et al., IEEE TKDE, 36(4), 2024, pp. 1813–1828. DOI: [10.1109/TKDE.2023.3304839](https://doi.org/10.1109/TKDE.2023.3304839).

- **Идея.** FANP заменяет фиксированное гауссово латентное распределение на normalizing flow и отдельно использует task-specific и task-relevant представления для адаптации декодера.
- **Значение для проекта.** Второй основной бейзлайн: позволяет проверить, решает ли более гибкая адаптация проблему неуместного переноса.
- **Ограничение.** Обучаемый gate оптимизируется по общей функции потерь и сам по себе не гарантирует отсутствия вреда для конкретного пользователя.

### 3. MeLU — Meta-Learned User Preference Estimator for Cold-Start Recommendation

**Источник:** H. Lee et al., KDD 2019, pp. 1073–1082. [Страница ACM](https://dl.acm.org/doi/10.1145/3292500.3330859) · [Код](https://github.com/hoyeoplee/MeLU)

- **Идея.** С помощью MAML обучается общая инициализация модели предпочтений, которую можно быстро дообучить на нескольких взаимодействиях нового пользователя.
- **Значение для проекта.** Простой и известный метаобучающий бейзлайн без явных кластерных центроидов.
- **Ограничение.** Одна общая инициализация может быть плохо согласована с неоднородными группами пользователей.

### 4. Meta-Learning for User Cold-Start Recommendation (MetaCS)

**Источник:** H. Bharadhwaj, IJCNN 2019, pp. 1–8. [Страница IEEE](https://ieeexplore.ieee.org/document/8852100)

- **Идея.** Cold start формулируется как быстрое обучение новой пользовательской задачи на малом support-наборе.
- **Значение для проекта.** Показывает базовую постановку «один пользователь — одна задача», принятую в последующих работах.
- **Ограничение.** Не моделирует явно различную полезность знаний других пользователей.

### 5. S2Meta — Sequential Scenario-Specific Meta Learner for Online Recommendation

**Источник:** Z. Du et al., KDD 2019, pp. 2895–2904. [Страница ACM](https://dl.acm.org/doi/10.1145/3292500.3330710)

- **Идея.** Метаобучение адаптируется не только к пользователю, но и к последовательному сценарию рекомендаций.
- **Значение для проекта.** Подчеркивает, что полезность переноса зависит от контекста задачи.
- **Ограничение.** Основной фокус — сценарная адаптация, а не диагностика отрицательного влияния группового знания.

### 6. MAMO — Memory-Augmented Meta-Optimization for Cold-Start Recommendation

**Источник:** M. Dong et al., KDD 2020, pp. 688–697. [Страница ACM](https://dl.acm.org/doi/10.1145/3394486.3403113) · [Код](https://github.com/dongmanqing/Code-for-MAMO)

- **Идея.** Память хранит профильные паттерны и быстро формирует персонализированную инициализацию для нового пользователя.
- **Значение для проекта.** Альтернативный способ переносить локальное, а не полностью глобальное знание.
- **Ограничение.** Чтение из памяти также может выбрать нерелевантный паттерн; индивидуальный вред переноса специально не измеряется.

### 7. MetaHIN — Meta-Learning on Heterogeneous Information Networks for Cold-Start Recommendation

**Источник:** Y. Lu, Y. Fang, C. Shi, KDD 2020, pp. 1563–1573. [Страница ACM](https://doi.org/10.1145/3394486.3403207) · [Код](https://github.com/rootlu/MetaHIN)

- **Идея.** Пользовательская задача дополняется семантикой гетерогенной сети и meta-path-представлениями.
- **Значение для проекта.** Показывает, как дополнительная структура может помочь выбирать релевантное знание.
- **Ограничение.** Требует богатых связей и атрибутов, которых нет во всех рекомендательных данных.

### 8. CMML — Contextual Modulation Meta Learning for Cold-Start Recommendation

**Источник:** X. Feng et al., CIKM 2021, pp. 484–493. [Страница ACM](https://dl.acm.org/doi/10.1145/3459637.3482238)

- **Идея.** Контекст задачи напрямую модулирует параметры рекомендателя, позволяя обходиться без нескольких градиентных шагов внутреннего цикла.
- **Значение для проекта.** Близкий к FANP пример адаптации параметров по контексту пользователя.
- **Ограничение.** Контекстная модуляция повышает гибкость, но не вводит явный критерий безопасного переноса.

### 9. PAML — Preference-Adaptive Meta-Learning for Cold-Start Recommendation

**Источник:** L. Wang et al., 2021. [Препринт](https://arxiv.org/abs/2107.05776)

- **Идея.** Похожие пользователи должны разделять более похожее prior-знание; глобальная инициализация локально адаптируется к предпочтениям.
- **Значение для проекта.** Одна из наиболее близких работ: она уже признает, что единое знание для всех пользователей может быть неуместным.
- **Ограничение.** Работа улучшает средний результат, но не ставит основной целью измерение случаев, когда перенос хуже персонального варианта без группового знания.

### 10. AdaML — Adaptive Meta-Learning Based on User Relevance

**Источник:** J. Xu et al., Knowledge-Based Systems, 279, 2023, 110925. DOI: [10.1016/j.knosys.2023.110925](https://doi.org/10.1016/j.knosys.2023.110925).

- **Идея.** Связанные пользователи определяются одновременно кластеризацией и meta-path-структурой; их информация используется для представления пользователя и relevance-specific prior.
- **Значение для проекта.** Прямое доказательство актуальности выбора релевантной группы пользователей.
- **Ограничение.** Нужна гетерогенная сеть; динамические веса не исключают ошибочного переноса и не дают отдельной оценки его частоты.

### 11. AdaMO — Adaptive Meta-Optimization for Cold-Start Recommendation

**Источник:** Neurocomputing, 580, 2024, 127417. DOI: [10.1016/j.neucom.2024.127417](https://doi.org/10.1016/j.neucom.2024.127417).

- **Идея.** Метод персонализирует исходное meta-знание и стратегию обновления на cold-start- и warm-up-этапах.
- **Значение для проекта.** Показывает современный переход от одной общей инициализации к адаптивному переносу.
- **Ограничение.** Баланс общего и личного знания оценивается в основном по агрегированному качеству, а не через индивидуальное сравнение с режимом без переноса.

### 12. Dual Enhanced Meta-Learning With Adaptive Task Scheduler for Cold-Start Recommendation

**Источник:** IEEE TKDE, 37(4), 2025, pp. 1728–1741. DOI: [10.1109/TKDE.2025.3529525](https://doi.org/10.1109/TKDE.2025.3529525).

- **Идея.** Планировщик оценивает meta-задачи по loss и сходству градиентов и снижает вероятность выбора шумных задач.
- **Значение для проекта.** Наиболее близкий современный механизм предотвращения плохого межзадачного переноса; его критерии можно использовать как ориентир для собственного улучшения.
- **Ограничение.** Фильтрация работает на уровне обучающих задач и не равна проверке полезности конкретного центроида для конкретного нового пользователя.

### 13. Comprehensive Review of Meta-Learning Methods for Cold-Start Issue in Recommendation Systems

**Источник:** IEEE Access, 13, 2025, pp. 24622–24641. DOI: [10.1109/ACCESS.2025.3536025](https://doi.org/10.1109/ACCESS.2025.3536025).

- **Идея.** Систематический обзор экспериментальных meta-learning-методов cold start, опубликованных до июня 2024 года.
- **Значение для проекта.** Используется для проверки полноты терминологии, классов методов и стандартных схем оценки.
- **Ограничение.** Это вторичный источник; вывод о новизне проекта должен опираться также на первичные статьи.

## 2. Альтернативные постановки и методы cold start

### 14. A Meta-Learning Perspective on Cold-Start Recommendations for Items

**Источник:** M. Vartak et al., NeurIPS 2017, pp. 6904–6914. [Материалы NeurIPS](https://proceedings.neurips.cc/paper/2017/hash/51e6d6e679953c6311757004d8cbbba9-Abstract.html)

- **Идея.** Метаобучение применяется к быстрому построению модели нового объекта.
- **Значение для проекта.** Демонстрирует переносимость постановки на item cold start и помогает отделить пользовательский сценарий от более общей проблемы.
- **Ограничение.** Объект адаптации — новый item, поэтому экспериментальная постановка не совпадает с нашей.

### 15. DropoutNet — Addressing Cold Start in Recommender Systems

**Источник:** M. Volkovs, G. Yu, T. Poutanen, NeurIPS 2017, pp. 4957–4966. [Материалы NeurIPS](https://proceedings.neurips.cc/paper/2017/hash/dbd22ba3bd0df8f385bdac3e9f8be207-Abstract.html)

- **Идея.** Во время обучения коллаборативные признаки случайно удаляются, чтобы модель умела работать по контентным признакам в cold-start-режиме.
- **Значение для проекта.** Альтернатива переносу между пользовательскими задачами и потенциальный внешний бейзлайн.
- **Ограничение.** Не моделирует явно групповое пользовательское знание.

### 16. MTPR — How to Learn Item Representation for Cold-Start Multimedia Recommendation?

**Источник:** X. Du et al., ACM Multimedia 2020, pp. 3469–3477. [Страница ACM](https://dl.acm.org/doi/10.1145/3394171.3413766)

- **Идея.** Обучается перенос от мультимодальных признаков объекта к представлению, пригодному для ранжирования.
- **Значение для проекта.** Показывает другой тип transfer learning в рекомендациях и помогает не смешивать его с переносом между пользовательскими задачами.
- **Ограничение.** Ориентирован на новые мультимедийные объекты, а не на новых пользователей.

### 17. CLCRec — Contrastive Learning for Cold-Start Recommendation

**Источник:** Y. Wei et al., ACM Multimedia 2021, pp. 5382–5390. [Страница ACM](https://dl.acm.org/doi/10.1145/3474085.3475665)

- **Идея.** Контрастивное обучение согласует контентное и коллаборативное представления для переноса знания на cold items.
- **Значение для проекта.** Дает альтернативный способ контролировать структуру переносимого представления.
- **Ограничение.** Не анализирует пользовательские задачи и вред от выбора нерелевантной группы.

## 3. Нейронные процессы и адаптация

### 18. Neural Processes

**Источник:** M. Garnelo et al., ICML Workshop 2018. [Препринт](https://arxiv.org/abs/1807.01622)

- **Идея.** Нейронная сеть обучается распределению над функциями и по небольшому контексту предсказывает значения в новых точках.
- **Значение для проекта.** Теоретическая основа вероятностной части TaNP/FANP.
- **Ограничение.** Базовая работа не предназначена специально для рекомендаций и не моделирует неоднородность пользователей.

### 19. Conditional Neural Processes

**Источник:** M. Garnelo et al., ICML 2018, pp. 1690–1699. [PMLR](https://proceedings.mlr.press/v80/garnelo18a.html)

- **Идея.** Контекстные пары кодируются, агрегируются в одно представление и используются для условного предсказания.
- **Значение для проекта.** Объясняет базовую схему «support → представление задачи → query prediction».
- **Ограничение.** Простая агрегация может терять структуру контекста и недооценивать неопределенность.

### 20. Attentive Neural Processes

**Источник:** H. Kim et al., ICLR 2019. [OpenReview](https://openreview.net/forum?id=SkE6PjC9KX)

- **Идея.** Attention делает представление контекста зависимым от точки запроса и уменьшает потерю информации при усреднении.
- **Значение для проекта.** Возможное направление улучшения выбора релевантного знания для конкретного кандидата.
- **Ограничение.** Attention повышает выразительность, но не является гарантией отсутствия отрицательного переноса.

### 21. CNAPS — Conditional Neural Adaptive Processes

**Источник:** J. Requeima et al., NeurIPS 2019, pp. 7957–7968. [Материалы NeurIPS](https://proceedings.neurips.cc/paper/2019/hash/6e2713a6efee97bacb63e52c54f0ada0-Abstract.html)

- **Идея.** По support-набору условно генерируются параметры модели для новой задачи.
- **Значение для проекта.** Архитектурный пример отделения механизма адаптации от общего представления.
- **Ограничение.** Исходная задача — few-shot-классификация, поэтому перенос в рекомендации требует отдельной проверки.

### 22. MetaFun — Meta-Learning With Iterative Functional Updates

**Источник:** J. Xu et al., ICML 2020, pp. 10617–10627. [PMLR](https://proceedings.mlr.press/v119/xu20b.html)

- **Идея.** Функциональное представление задачи уточняется несколькими обученными итеративными обновлениями.
- **Значение для проекта.** Альтернатива однократному смешиванию личного и группового представлений.
- **Ограничение.** Более сложное итеративное обновление увеличивает вычислительную стоимость и само по себе не задает критерий безопасного переноса.

### 23. MAML — Model-Agnostic Meta-Learning for Fast Adaptation of Deep Networks

**Источник:** C. Finn, P. Abbeel, S. Levine, ICML 2017, pp. 1126–1135. [PMLR](https://proceedings.mlr.press/v70/finn17a.html)

- **Идея.** Обучается такая общая инициализация параметров, из которой достаточно нескольких градиентных шагов для новой задачи.
- **Значение для проекта.** Основа MeLU, MetaCS и многих последующих cold-start-методов.
- **Ограничение.** Одна инициализация предполагает достаточную согласованность задач; при сильной неоднородности возможен конфликт переноса.

### 24. FiLM — Visual Reasoning With a General Conditioning Layer

**Источник:** E. Perez et al., AAAI 2018, pp. 3942–3951. [Статья AAAI](https://ojs.aaai.org/index.php/AAAI/article/view/11671)

- **Идея.** Условный вектор задает покомпонентные масштаб и сдвиг промежуточных признаков сети.
- **Значение для проекта.** Это механизм адаптации в варианте TaNP Gating-FiLM, который мы воспроизводим.
- **Ограничение.** FiLM определяет способ модуляции, но не критерий выбора корректного внешнего знания.

## 4. Негативный перенос и конфликт задач

### 25. PCGrad — Gradient Surgery for Multi-Task Learning

**Источник:** T. Yu et al., NeurIPS 2020. [Материалы NeurIPS](https://proceedings.neurips.cc/paper/2020/hash/3fe78a8acf5fda99de95303940a2420c-Abstract.html)

- **Идея.** Если градиенты двух задач направлены конфликтно, компонент одного градиента, мешающий другому, проецируется из обновления.
- **Значение для проекта.** Дает операциональный способ диагностировать конфликт пользовательских задач и связать его с ухудшением рекомендаций.
- **Ограничение.** Метод разработан для multi-task-оптимизации, а не для выбора кластерных центроидов в нейронном процессе; перенос требует отдельного эксперимента.

## Вывод из обзора

Литература уже показывает, что единое глобальное знание подходит пользователям неодинаково. PAML и AdaML локализуют prior по похожим пользователям, FANP вводит task-adaptive модуляцию, AdaMO адаптирует инициализацию и обновление, а Dual Enhanced Meta-Learning фильтрует шумные meta-задачи. Поэтому утверждать, что сама идея «учитывать релевантность группового знания» нова, нельзя.

Остается более узкий и проверяемый пробел: в работах TaNP/FANP основное сравнение проводится по агрегированным метрикам, тогда как индивидуальные случаи, в которых добавление группового знания проигрывает варианту только с личным представлением, не являются самостоятельным объектом анализа. Первый этап проекта — воспроизвести TaNP и FANP и измерить такой эффект по пользователям, числу доступных взаимодействий и весам центроидов. Если эффект обнаружится устойчиво, следующий этап — проверить простой механизм ограничения или коррекции переноса.
